PAGE 01 — DESIGN PRINCIPLES

Purpose:
Define the behavioral and visual principles governing every interface decision.

Content:

1. Personal, not judgmental
2. Evidence-aware, not falsely precise
3. Progress-oriented, not guilt-oriented
4. AI-assisted, not AI-controlled
5. Reduction before contribution
6. Clear about estimates and uncertainty
7. Consistent across dark and light modes
8. Accessible without depending on color or icon recognition
9. Compact but readable
10. Connected to the main Bluence product family

Visual direction:

- Premium eco-futuristic character
- Dark fig foundations
- Aqua and olive progress signals
- Violet-to-blue AI identity
- Rounded, layered surfaces
- Restrained environmental symbolism
- Clear separation between estimated, planned, completed and verified states

Extended visual character:

- The interface must feel intelligent and data-driven without appearing clinical.
- Environmental identity is expressed through color, progress, verified-impact states and restrained leaf motifs rather than excessive green imagery.
- Dark fig-purple is the dominant brand foundation; aqua and olive function as progress and environmental accents.
- Blue represents information, navigation and analytical content.
- Soft gradients are reserved for AI identity, primary action, active pathways and a limited number of branded highlights.
- Rounded layered surfaces make the personal application feel more supportive than the enterprise application while maintaining the same Bluence family identity.
- Information density must come from hierarchy, spacing and alignment—not from reducing text below readable sizes.

5.7 Typography usage rules

- Use Cinzel only for the principal page-level title or a major branded statement.
- Use no more than one gradient title in the same viewport.
- Do not use Cinzel for navigation, cards, forms, tables or long headings.
- Use Merriweather for meaningful editorial and sectional hierarchy, not every minor card label.
- Do not use Cinzel or Merriweather in all-uppercase text.
- Use Poppins for readable, conversational and explanatory content.
- Use Inter or Segoe UI for navigation, interaction, dense data and numerical content.
- Carbon values, percentages and token balances use Inter with tabular numerals.
- Gradient text is prohibited for instructions, warnings, legal content and accessibility-critical information.
- Normal body copy must remain at least 16 px; secondary metadata must remain at least 12 px.
- Establish hierarchy through role, weight and spacing before adding extra color.

- Cinzel provides the PLANET-B identity.
- Merriweather provides editorial authority and warmth.
- Poppins provides approachable, human-centered reading.
- Inter and Segoe UI provide precision, density and interface clarity.

PAGE 08 — ICON-ONLY BUTTON USABILITY RULES

Purpose:
Prevent ambiguity and accessibility failures.

Mandatory requirements:

- Every button must have an accessible name
- Every desktop button must show a tooltip on hover and keyboard focus
- Tooltip language must describe the action, not the icon
- Tooltips should appear after approximately 300–500 ms
- Tooltips must not cover essential content
- Keyboard focus order must follow task order
- Repeated icons must always perform the same action
- Do not use the same icon for unrelated actions

Visible external captions are mandatory for:

- First-time onboarding actions
- Questionnaire progression
- Saving or submitting data
- Creating or changing targets
- Confirming a baseline update
- Verifying an achievement
- Spending tokens
- Confirming a donation
- Deleting personal data
- Any irreversible or legally meaningful action

Caption pattern:

[Circle icon button]
Confirm donation

The text is placed beside or below the button, but never inside it.

Mobile behavior:

- Do not depend on hover tooltips
- Use persistent captions for unfamiliar actions
- Provide onboarding hints for novel icons
- Use an action sheet when several icons could be ambiguous
- Do not require long press to discover meaning

Critical rule:

A circle containing only an icon is not sufficient when the consequence of the action is not immediately obvious.

- Cancel: cross
- Close: cross
- Back: arrow-left
- Continue: arrow-right

Rules:

- Consequential dialog actions require external captions
- Do not show two identical cross icons for different meanings
- Close and cancel must be distinguished by placement and context
- Keyboard focus must remain inside an open dialog


PAGE 24 — MOTION AND TRANSITIONS

Purpose:
Define functional movement.

Motion durations:

- Micro-interaction: 120–180 ms
- Standard state change: 200–250 ms
- Drawer or modal: 250–300 ms

Circular-button motion:

- Hover: subtle elevation or background shift
- Pressed: slight scale reduction, approximately 0.96–0.98
- Loading: rotating progress treatment
- Success: icon changes to check
- Error: color change without excessive shaking
- Floating button: no continuous pulsing

Rules:

- Avoid decorative animation
- Do not animate essential numbers continuously
- Respect reduced-motion preferences
- Motion must clarify state change

CORE CIRCULAR-BUTTON POLICY

Use icon-only circular buttons for:

- Familiar navigation actions
- Search
- Close
- Back
- Add
- Edit
- Filter
- Download
- Expand
- Open Copilot
- Repeated card actions

Use circular buttons with visible external captions for:

- Register
- Continue questionnaire
- Submit questionnaire
- Create baseline
- Set target
- Add recommendation to plan
- Confirm action completion
- Verify evidence
- Update baseline
- Spend tokens
- Confirm contribution
- Delete data or account

Never rely on an icon-only circle without a tooltip, accessible name or contextual explanation.
